## Guidance

Sidebar is a **vertical navigation rail** composed from **Button**, **Tooltip**, and **Divider** (`SidebarSeparator`). It does not reimplement button or tooltip styles. Toggle with `SidebarTrigger` (ghost **Button** `icon`). `variant` on the rail is `default` only; expanded vs collapsed is runtime state.

<Canvas of={SidebarStories.Default} />

## When to use / When not to use

Use Sidebar for app shell navigation along the left edge. Use **Navigation Menu** for horizontal top nav with dropdown panels. Do not merge their logic.

Do not use Sidebar for one-off menus; use Dropdown Menu or Navigation Menu.

## Do / Don't

**Do**

- Wrap layouts in `SidebarProvider`, then `Sidebar` + `SidebarInset`.
- Use `SidebarMenuButton` with `isActive` for the current page and `tooltip` when collapsed (labels hide; tooltip shows on hover).
- Use `SidebarSeparator` (Divider) between groups.

<Canvas of={SidebarStories.AsChild} />

**Don't**

- Don't restyle nav items outside **Button** ghost variants.
- Don't build nested tree nav unless Figma adds a pattern (not in this release).

## Accessibility in practice

`SidebarTrigger` exposes `aria-label="Toggle sidebar"`. Collapsed items rely on **Tooltip** for visible names; keep concise labels in `tooltip`. Active items set `data-active` on the **Button**.

## Content guidelines

- Group labels are short section titles (“Platform”, “Account”).
- Nav labels are one or two words (“Dashboard”, “Settings”).
- Tooltips repeat the nav label when collapsed.
